> 이 글은 **자율 실습 · 14문제**(개인 실습) 중 **보너스(2문제)**를 기록한 devlog입니다.
> 여유가 있을 때 푸는 문제로, Lv.1~Lv.3에서 다듬은 `/learn`을 실제로 며칠 써보며 점검하고, 스킬 파일을 최소선까지 줄여본다.
> 문제마다 `문제 상황 → 시도한 방법 → 막혔던 점 → 해결 과정 → 배운 점` 순서로 정리했다.

> 문제 원문: [Claude Artifact — 답을 주지 않는 AI](https://claude.ai/code/artifact/e3c61ac6-1063-46d8-bdf5-4d09fa2c21e4)

## 시작 전 공통 규칙

⚠️ 모든 문제에 적용되는 세 가지 규칙이 있다.

- 시키기 전에 커밋한다. 시작할 때마다 `git status`로 clean인지 확인한다.
- 스킬 파일을 고쳤으면 `/clear`한다. 안 하면 앞 대화가 남아 무엇 덕분에 답이 달라졌는지 알 수 없다.
- 재시작(`/exit` 후 다시 `claude`)은 스킬 **폴더를 새로 만들었을 때만** 필요하다. 파일만 고친 경우는 저장하는 즉시 반영된다.

💡 스킬이 `/` 목록에 안 뜨면 아래 순서로 확인한다.

- **폴더를 새로 만들었다** → `/exit` 하고 다시 `claude`
- **파일 이름이 다르다** → `SKILL.md`가 맞는지 확인한다(`learn.md`·`skill.md` 아님, 대문자)
- **폴더 이름이 다르다** → `learn`/`note`처럼 소문자인지 확인한다
- **위치가 다르다** → 저장소 맨 위 `my-blog/.claude/skills/...`인지 확인한다(`_posts` 안이면 안 된다)
- **저장을 안 했다** → `Ctrl+S`
- **목록에서 못 찾는 것뿐이다** → `/le`·`/no`까지 쳐서 좁힌다(목록에서 나가려면 `Esc`)

⚠️ `.claude`는 점으로 시작해서 파일 탐색기에는 안 보인다. 스킬 파일 작업은 VS Code에서 한다.

## 보너스 (2문제)

### 1. 사용 점검표 만들고 며칠 뒤 채우기

⏳ 표는 지금 만들고, 채우는 것은 며칠 뒤다. 오늘 안에 끝나지 않는 유일한 문제다.

#### 문제 상황
아래 점검표를 지금 만들어 두고, 며칠 실제로 써본 뒤 채운다. 그리고 그 결과를 보고 `/learn`을 고쳐 쓴다.

#### 시도한 방법
```
| 점검                        | 결과 |
| /learn 을 몇 번 불렀나       |      |
| 탈출구를 몇 번 썼나          |      |
| 안 지켜진 규칙이 있나        |      |
| 답답해서 안 부른 적이 있나   |      |
```

#### 막혔던 점
🔴 표를 만들어놓고도 실제로 며칠 써보기 전까지는 뭘 적어야 할지 감이 안 왔다.

#### 해결 과정
🟢 `/learn`을 부를 때마다, 그리고 탈출구("힌트 끝까지 줘")를 쓸 때마다 바로바로 표에 체크만 해두는 식으로 기록을 남겼다.

#### 배운 점
💡 탈출구를 자주 쓴다는 건 성장 규칙이 과하다는 신호다 — 기록해두지 않으면 이 패턴 자체를 알아채기 어렵다.

| 점검 | 결과 |
|---|---|
| `/learn`을 몇 번 불렀나 | 9번 |
| 탈출구를 몇 번 썼나 | 2번 |
| 안 지켜진 규칙이 있나 | 있음 — 짧은 질문엔 규칙을 무시하고 바로 답할 때가 있었다 |
| 답답해서 안 부른 적이 있나 | 있음 — 급할 때는 `/learn` 없이 그냥 물어봤다 |

탈출구를 쓴 2번 다 "당장 답이 급한" 상황이었어서, 성장 규칙에 "정말 급하면 '바로 알려줘'라고 말해도 된다"는 조건을 명시적으로 추가했다.

#### 확인 체크리스트
- [ ] 표가 실제 사용 기록으로 채워져 있다
- [ ] 탈출구를 자주 썼다면 성장 규칙을 줄였다
- [ ] 안 지켜진 규칙이 있다면 그 문장을 구체적으로 고쳐 썼다
- [ ] 고친 뒤 다시 시험해서 지켜지는 것을 확인했다

### 2. eli5 원본 보고 /learn 절반으로 줄이기

⚠️ eli5를 설치한 경우에만 푼다. ⛔ 줄이기 전에 커밋한다. 결과가 나쁘면 되돌린다.

#### 문제 상황
eli5의 원본을 다시 읽고 왜 5줄로 충분한지 설명한다. 그다음 자기 `/learn`을 절반 길이로 줄여보고, 답이 그대로인지 확인한다.

#### 시도한 방법
```
① git add .claude
   git commit -m "줄이기 전"
② 지워도 될 것 같은 줄에 표시
③ 지우고 저장 → /clear → 세 가지 다 시험(되묻기 · 탈출구 · 경계)
④ 나빠졌으면 git restore .claude/skills/learn/SKILL.md
```

#### 막혔던 점
🔴 어디까지 지워도 되는지 감이 안 와서, `CLAUDE.md`에 이미 있는 내용(예: 블로그 규칙)까지 `SKILL.md`에 다시 적어둔 줄을 처음엔 못 찾았다.

#### 해결 과정
🟢 `CLAUDE.md`를 먼저 열어 이미 적힌 내용과 `SKILL.md`를 한 줄씩 대조하니, AI가 어차피 아는 것을 `SKILL.md`에 중복해서 적어둔 줄이 여럿 보였다.

#### 배운 점
💡 eli5가 5줄로 충분한 건 AI가 이미 아는 것을 다시 적지 않기 때문이다 — 스킬 파일도 마찬가지로, `CLAUDE.md`에 이미 있는 내용은 스킬에 또 적을 필요가 없다.

원래 `SKILL.md`는 28줄이었는데, `CLAUDE.md`에 이미 있는 블로그 규칙 설명과 예시 문장을 지우고 나니 16줄로 줄었다. 한 번은 "탈출구" 항목을 통째로 지웠다가 `/clear` 후 시험해보니 "힌트 끝까지 줘"가 안 먹혀서, `git restore`로 그 줄만 되돌렸다.

#### 확인 체크리스트
- [ ] eli5가 5줄로 되는 이유가 한 문단으로 적혀 있다
- [ ] `/learn`이 눈에 띄게 짧아졌다
- [ ] 짧아진 뒤에도 되묻기·탈출구·경계가 그대로 동작한다
- [ ] 나빠졌다면 `git restore`로 되돌리고 어느 줄이 꼭 필요했는지 적었다

## 보너스 두 문제를 풀어보고 나서

열네 문제를 통틀어 가장 인상 깊었던 건 Lv.1 3번(규칙 다 지우고 비교하기)이었다 — 규칙이 없을 때 답이 편해 보이지만 실제로는 내가 생각할 기회를 뺏는다는 걸 눈으로 본 게 가장 컸다. `/learn`은 처음엔 역할·규칙이 뭉뚱그려진 28줄짜리 파일이었는데, 최종본은 역할·성장·탈출구·경계가 각각 예시로 나뉘고 줄 수는 16줄로 줄면서 오히려 더 잘 지켜졌다.

## 더 학습하면 좋은 개념

- **Claude Code 플러그인 마켓플레이스** — eli5 같은 스킬을 설치·관리하는 방식(2번 문제)을 공식 문서로 더 볼 수 있다.
- **컨텍스트 관리(Context Window) 원칙** — 스킬 파일이 짧을수록 매번 읽는 양이 준다는 감각(2번 문제)은, 긴 대화·긴 프롬프트에서 컨텍스트를 관리하는 공식 가이드와 이어진다.
- **자기 점검 로그(Self-Review Checklist)** — 1번 문제의 점검표처럼, 도구 사용 패턴을 기록해서 규칙을 조정하는 습관은 다른 자동화 도구에도 그대로 적용된다.
