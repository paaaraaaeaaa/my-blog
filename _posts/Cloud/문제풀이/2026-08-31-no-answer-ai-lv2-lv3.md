> 이 글은 **자율 실습 · 14문제**(개인 실습) 중 **Lv.2 — 응용(4문제)**과 **Lv.3 — 도전(2문제)**을 기록한 devlog입니다.
> Lv.1에서 역할·규칙 칸을 나눠보는 감각을 익힌 뒤, 이번엔 경계 규칙을 실제 질문 5개로 검증하고, 스킬을 다른 주제·다른 저장소로 옮겨보고, 마지막엔 "한 줄 지시로 매번 같은 결과가 나오게" `CLAUDE.md`와 `/note`를 직접 설계하는 단계로 넘어간다.
> 문제마다 `문제 상황 → 시도한 방법 → 막혔던 점 → 해결 과정 → 배운 점` 순서로 정리했다.

> 문제 원문: [Claude Artifact — 답을 주지 않는 AI](https://claude.ai/code/artifact/e3c61ac6-1063-46d8-bdf5-4d09fa2c21e4)

## 시작 전 공통 규칙

⚠️ 모든 문제에 적용되는 세 가지 규칙이 있다.

- 시키기 전에 커밋한다. 시작할 때마다 `git status`로 clean인지 확인한다.
- 스킬 파일을 고쳤으면 `/clear`한다. 안 하면 앞 대화가 남아 무엇 덕분에 답이 달라졌는지 알 수 없다.
- 재시작(`/exit` 후 다시 `claude`)은 스킬 **폴더를 새로 만들었을 때만** 필요하다. 파일만 고친 경우는 저장하는 즉시 반영된다.

💡 스킬이 `/` 목록에 안 뜨면 아래 순서로 확인한다.

- **폴더를 새로 만들었다** → `/exit` 하고 다시 `claude`
- **파일 이름이 다르다** → `SKILL.md`가 맞는지 확인한다(`learn.md`·`skill.md` 아님, 대문자)
- **폴더 이름이 다르다** → `learn`/`note`처럼 소문자인지 확인한다
- **위치가 다르다** → 저장소 맨 위 `my-blog/.claude/skills/...`인지 확인한다(`_posts` 안이면 안 된다)
- **저장을 안 했다** → `Ctrl+S`
- **목록에서 못 찾는 것뿐이다** → `/le`·`/no`까지 쳐서 좁힌다(목록에서 나가려면 `Esc`)

⚠️ `.claude`는 점으로 시작해서 파일 탐색기에는 안 보인다. 스킬 파일 작업은 VS Code에서 한다.

## Lv.2 — 응용 (4문제)

### 1. 답이 하나뿐인 질문 5개로 경계 규칙 다듬기

⚠️⚠️ 질문마다 `/clear → /learn → 질문` 세 단계를 지킨다. `/clear`만 하고 `/learn`을 다시 안 부르면 스킬이 안 걸린 맨 대화라서, 규칙을 하나도 안 고쳐도 5개 전부 통과가 나온다.

#### 문제 상황
답이 하나뿐인 질문(오타·명령어 철자·설치 오류·파일 이름 규칙 등) 5개를 직접 만들어 `/learn`에 하나씩 던진다. 되묻는 질문이 하나라도 있으면 경계 규칙을 고쳐서 5개가 전부 바로 답할 때까지 반복한다.

#### 시도한 방법
```
| 질문                              | 되물었나 | 고친 규칙 |
| gti status 라고 쳤는데 왜 안 되죠   |         |          |
| ...(5개)                          |         |          |
```
경계 규칙 뼈대: `- ____, ____, ____ 처럼 답이 하나뿐인 건 바로 알려줘.`

#### 막혔던 점
🔴 처음 5개 중 2개가 계속 되물어서 살펴보니, 경계 규칙에 "오타"만 적어뒀던 게 원인이었다 — "명령어 철자"와 "설치 오류"는 다른 종류로 안 걸렸다.

#### 해결 과정
🟢 되물은 질문들의 공통점을 찾아 경계 규칙에 종류를 예로 나열하니("오타, 명령어 철자, 설치 오류처럼...") 5개 전부 바로 답했다.

#### 배운 점
💡 경계 규칙은 추상적으로 쓰면 안 먹힌다. "답이 하나뿐인 것"을 종류별로 예를 들어 나열해야 실제로 걸린다.

---

### 2. 되물었던 질문을 좁혀서 다시 던지기

#### 문제 상황
`/learn`이 되물었던 질문을 하나 고른다. 이번엔 AI가 물어볼 것을 미리 답해서 질문에 넣고 다시 던진다. 규칙은 한 글자도 고치지 않는다.

#### 시도한 방법
```
전: 브랜치를 잘못 만들었는데 어떻게 되돌리죠?
후: 브랜치를 하나 만들었는데 ____________ , 그냥 지우고 싶어요
```

#### 막혔던 점
🔴 처음엔 "후" 질문도 그냥 문장을 길게 늘리기만 해서 여전히 되물었다.

#### 해결 과정
🟢 되물었던 문장이 정확히 무엇을 모르는지(예: 커밋했는지 안 했는지, 원격에 push했는지) 읽고 그 정보만 골라 채우니 바로 답이 나왔다.

#### 배운 점
💡 좁혀 묻기는 길게 쓰는 게 아니라, AI가 되물은 그 지점(대상과 범위)만 채우는 것이다.

---

### 3. 개발 아닌 주제로 새 /learn 스킬 만들기

⚠️ 폴더를 새로 만들었으므로 재시작이 필요할 수 있다.

#### 문제 상황
운동·요리·외국어 등 개발이 아닌 주제로 `/learn`을 하나 더 만든다. 폴더 이름을 `learn`과 다르게 하고, 경계 규칙을 그 주제에 맞게 고친다.

#### 시도한 방법
```
.claude/skills/____/SKILL.md

## 규칙 — 되묻지 말아야 할 때

- ____, ____ 처럼 답이 하나뿐인 건 바로 알려줘.
```

#### 막혔던 점
🔴 새 폴더를 만들고 저장까지 했는데 `/` 목록에 안 보여서, 파일만 고쳤을 때와 달리 이번엔 재시작이 필요하다는 걸 놓칠 뻔했다.

#### 해결 과정
🟢 `/exit` 후 다시 `claude`를 켜니 목록에 새 스킬이 보였다.

#### 배운 점
💡 "답이 하나뿐인 것"은 주제마다 다르다 — 개발에서는 오타였지만, 요리에서는 계량 단위나 정확한 온도처럼 안전과 직결된 것이 그 자리를 대신한다.

---

### 4. /note를 다른 저장소(blog-plan)에 옮겨 심기

#### 문제 상황
다른 저장소(blog-plan)에 `/note`를 옮겨 심는다. 복사가 아니라 그 저장소에 맞게 고쳐서 넣는다. blog-plan에는 블로그 규칙(`CLAUDE.md`)이 없다는 점을 감안한다.

#### 시도한 방법
```
blog-plan/.claude/skills/note/SKILL.md
```
my-blog의 `/note` 2번 줄(`CLAUDE.md` 참조 부분)을 그 저장소에 맞게 고친다. 필요하면 blog-plan에도 `CLAUDE.md`를 만든다.

#### 막혔던 점
🔴 그대로 복사했더니 blog-plan에서 실행했을 때 `_posts`나 머리말 같은, my-blog에만 있는 규칙을 계속 언급했다.

#### 해결 과정
🟢 `CLAUDE.md`를 참조하는 줄을 지우고 blog-plan 상황에 맞는 최소한의 규칙만 남기니 더 이상 my-blog 규칙을 말하지 않았다.

#### 배운 점
💡 스킬은 그 저장소 안에서만 동작한다 — 복사해서 옮겨도 다른 저장소의 전제(`CLAUDE.md` 같은)까지 따라오지는 않는다.

## Lv.3 — 도전 (2문제)

### 1. 한 줄 지시로 매번 같은 결과 나오게 만들기

⭐ 여기서 만든 것을 남은 과정 내내 쓴다.

#### 문제 상황
"○○로 글 하나 써줘" 한 줄만 치면 되고, 그 뒤로 규칙을 설명하거나 위치를 알려주는 일이 한 번도 없어야 하며, 결과물은 매번 같은 양식이어야 한다. `CLAUDE.md`와 `/note`를 필요한 만큼 고쳐서 이 조건을 만족시키고, 매번 다른 주제로 3회(매번 `/clear` 후) 돌려서 확인한다.

#### 시도한 방법
```
| 회차 | 내가 추가로 말한 것 | 어디로 옮겼나 |
| 1회 |                    |              |
| 2회 |                    |              |
| 3회 | (없어야 한다)       |              |
```

#### 막혔던 점
🔴 1회차에는 결과가 나온 뒤에도 파일 저장 위치와 태그 개수를 추가로 한 번 더 설명해야 했다.

#### 해결 과정
🟢 "말해야 했던 게 늘 참인 사실이면 CLAUDE.md, 순서면 /note로 간다"는 기준으로, 저장 위치는 `CLAUDE.md`에 이미 있는지 확인하고 태그 개수는 `/note` 순서에 명시했다.

#### 배운 점
💡 한 번에 완성되지 않는다 — 1회차에 추가로 설명하게 된 것이 곧 2회차에 고칠 대상이 된다.

1회차(주제: Git 브랜치 전략)에는 저장 위치와 태그 개수를 추가로 말해야 했고, 저장 위치는 `CLAUDE.md`에, 태그 개수는 `/note` 순서에 각각 반영했다. 2회차(주제: Docker 컨테이너 기초)에는 제목에 콜론을 썼는데 따옴표로 안 감싸서 한 번 더 고쳐야 했다 — 이건 `CLAUDE.md`의 Front Matter 규칙에 이미 있던 내용을 `/note`가 안 따르고 있었던 것이라, `/note` 순서에 "제목은 CLAUDE.md의 Front Matter 규칙을 그대로 따른다"는 줄을 추가했다. 3회차(주제: React Query 캐싱)는 "뭘 배웠어요?"에 답하고 글을 확인한 것 말고는 더 말한 게 없었다.

#### 확인 체크리스트
- [ ] 3회 모두 `/note` 한 줄로 시작했다
- [ ] 3회 모두 글이 블로그에 실제로 보인다
- [ ] 회차마다 무엇이 불편했고 무엇을 고쳤는지 적혀 있다
- [ ] 3회차에는 내가 한 일이 답하기와 확인하기뿐이었다

---

### 2. 무슨 글을 쓸까 도와주는 세 번째 스킬 설계

⭐ 성장 규칙을 넣을지 말지 직접 정하고 이유를 적는다. 💡 정답이 없다 — 근거가 있으면 맞는 답이다.

#### 문제 상황
내 블로그를 보고 아직 안 쓴 주제를 찾아주는 세 번째 스킬을 설계한다.

#### 시도한 방법
```
.claude/skills/____/SKILL.md

# 무엇을 하는 스킬인가
1. ____
2. ____

내 판단: 성장 규칙을 (넣었다 / 안 넣었다)
이유: ____
```

#### 막혔던 점
🔴 "이 스킬은 나를 키우는 도구인가, 일을 끝내는 도구인가"를 처음엔 판단하기 어려웠다 — 주제를 찾아주는 것도 어떻게 보면 학습에 도움이 되는 것 같았다.

#### 해결 과정
🟢 `/learn`과 `/note`의 차이(성장 규칙 있음/없음)를 기준으로, 이 스킬이 "내가 직접 답을 찾게 만드는가" 아니면 "결과를 빠르게 끝내주는가"를 다시 물어보고 판단했다.

#### 배운 점
💡 정답이 없는 문제도 근거가 있으면 맞는 답이 된다 — 중요한 건 결론이 아니라 왜 그렇게 정했는지를 설명할 수 있는가다.

## Lv.2~Lv.3 여섯 문제를 풀어보고 나서

여섯 문제 중 가장 오래 걸린 건 Lv.3 1번이었다. 매번 다른 주제로 세 번을 돌려야 했고, 회차마다 뭐가 불편했는지 놓치지 않고 적어야 해서 시간이 걸렸다. `CLAUDE.md`는 1회차엔 글 내용 규칙만 있었는데 최종본에는 저장 위치·Front Matter 형식까지 명시됐고, `/note`는 1회차의 3단계짜리 순서에서 최종본은 5단계(제목 확인 → 태그 확인 → 글 생성 → 커밋 → push 확인)로 늘었다.

## 더 학습하면 좋은 개념

- **좁혀 묻기 / 프롬프트에서 컨텍스트 명시하기** — 2번 문제처럼 AI가 되물은 지점만 채워 다시 묻는 감각은, 프롬프트에 필요한 컨텍스트를 명시적으로 넣는 공식 가이드의 기초가 된다.
- **Claude Code 프로젝트별 설정(.claude 디렉터리)** — 4번 문제(다른 저장소에 스킬 옮기기)처럼 스킬이 저장소마다 독립적으로 동작하는 이유를 공식 문서에서 더 볼 수 있다.
- **요구사항 분해(Requirement Decomposition)** — Lv.3 1번 문제에서 "한 줄로 끝나게" 만들려면, 매번 반복되는 요구사항과 그때그때 다른 요구사항을 구분해서 각각 `CLAUDE.md`/스킬로 나누는 감각이 필요하다.
- **에이전트/도구 설계 원칙(목적에 따른 규칙 분리)** — Lv.3 2번 문제(성장 규칙 넣을지 판단)처럼, 도구마다 목적이 다르면 규칙도 달라야 한다는 감각은 에이전트나 도구를 설계할 때 반복해서 쓰인다.
