> 역할도 출력 형식도 그대로 두고 규칙 칸 하나만 채웠는데 답이 완전히 달라지는 걸 확인하면서, `/learn`·`/note` 스킬의 어디까지가 "내 것"인지 하나씩 흔들어봤다.
> 문제마다 `문제 상황 → 시도한 방법 → 막혔던 점 → 해결 과정 → 배운 점` 순서로 정리했다.

## 시작 전 공통 규칙

⚠️ 모든 문제에 적용되는 세 가지 규칙이 있다.

- 시키기 전에 커밋한다. 시작할 때마다 `git status`로 clean인지 확인한다.
- 스킬 파일을 고쳤으면 `/clear`한다. 안 하면 앞 대화가 남아 무엇 덕분에 답이 달라졌는지 알 수 없다.
- 재시작(`/exit` 후 다시 `claude`)은 스킬 **폴더를 새로 만들었을 때만** 필요하다. 파일만 고친 경우는 저장하는 즉시 반영된다.

💡 스킬이 `/` 목록에 안 뜨면 아래 순서로 확인한다.

- **폴더를 새로 만들었다** → `/exit` 하고 다시 `claude`
- **파일 이름이 다르다** → `SKILL.md`가 맞는지 확인한다(`learn.md`·`skill.md` 아님, 대문자)
- **폴더 이름이 다르다** → `learn`/`note`처럼 소문자인지 확인한다
- **위치가 다르다** → 저장소 맨 위 `my-blog/.claude/skills/...`인지 확인한다(`_posts` 안이면 안 된다)
- **저장을 안 했다** → `Ctrl+S`
- **목록에서 못 찾는 것뿐이다** → `/le`·`/no`까지 쳐서 좁힌다(목록에서 나가려면 `Esc`)

⚠️ `.claude`는 점으로 시작해서 파일 탐색기에는 안 보인다. 스킬 파일 작업은 VS Code에서 한다.

## Lv.1 — 기본 변형 (6문제)

### 1. /learn 역할 한 줄만 바꾸기

#### 문제 상황
`/learn`의 `## 역할` 한 줄만 바꾸고 나머지(특히 `## 규칙`)는 한 글자도 건드리지 않는다. 예: "너는 내 학습을 돕는 선생님이다" → "너는 나와 같이 공부하는 동료다". 바꾼 뒤 `/clear`하고 수업에서 썼던 질문을 그대로 다시 던져서, 되묻는 성장 규칙은 그대로인지 말투·태도만 달라지는지 확인한다.

#### 시도한 방법
```
## 역할

너는 ____________ 다.
나는 프로그래밍을 이제 막 배우기 시작했고, 매일 배운 것을 블로그에 정리한다.
```
고친 뒤 저장 → `/clear` → `/learn` → 같은 질문.

#### 막혔던 점
🔴 처음에는 "역할"과 "규칙"이 뭐가 다른지 감이 안 와서, 역할 문장에 규칙에 들어갈 법한 말("차근차근 알려줘")까지 같이 써버릴 뻔했다.

#### 해결 과정
🟢 역할은 "누구로서 답하는가", 규칙은 "어떻게 답하는가"로 나눠서 생각하니 역할 칸에는 관계·태도만 남기고 나머지는 그대로 뒀다.

#### 배운 점
💡 역할 문장만 바꿔도 되묻는 행동(성장 규칙)은 그대로고 말투만 달라진다 — "무엇을 하는가"와 "누구로서 하는가"는 서로 다른 칸에서 따로 결정된다.

---

### 2. /learn 성장 규칙 한 줄 더 넣기

#### 문제 상황
`/learn`의 성장 규칙(답을 바로 안 주는 계열)에 자기 말로 한 줄을 더 넣는다. 넣기 전에 "이 문장을 읽고 AI가 무엇을 할지 한 가지로 정해지는가"를 스스로 판정한다.

#### 시도한 방법
```
## 규칙 — 답을 바로 주지 않기

- (기존 세 줄)
- ____________________________
```

#### 막혔던 점
🔴 처음 쓴 문장이 "친절하게 설명해줘"처럼 추상적이라, 넣어도 실제 답이 달라지지 않았다.

#### 해결 과정
🟢 "무엇을 하라는 건지 한 가지로" 정해지는 문장으로 바꿔 쓰니(예: "내가 시도한 방법을 먼저 말하게 하고, 그다음에만 힌트를 줘") `/clear` 후 질문했을 때 그 규칙이 실제로 지켜지는 게 보였다.

#### 배운 점
💡 안 지켜지는 규칙은 거의 항상 문장이 추상적이다. 판정 기준은 한 가지 — "이 문장을 읽고 AI가 할 일이 한 가지로 정해지는가"다.

---

### 3. 규칙 세 덩이 지웠다가 되돌리기

⛔ 먼저 커밋한다. 지우기 전에 커밋해 두면 손으로 다시 칠 필요가 없다.

#### 문제 상황
`git add .claude` → `git commit -m "스킬 실험 전 상태"`로 먼저 커밋한다. 그다음 `/learn`에서 `## 규칙` 세 덩이(성장·탈출구·경계)를 전부 지운다. `/clear` 후 같은 질문을 던져 답이 그냥 답하는 형태(A)로 돌아오는지 보고, 확인이 끝나면 `git restore`로 되돌린다.

#### 시도한 방법
```
① git add .claude
   git commit -m "스킬 실험 전 상태"
② SKILL.md에서 ## 규칙 부분 전부 삭제 → 저장
③ /clear → /learn → 같은 질문 → 답을 적는다
④ git restore .claude/skills/learn/SKILL.md
⑤ /clear → /learn → 같은 질문 → 되묻는지 확인
```

#### 막혔던 점
🔴 규칙을 다 지운 채로 질문했더니 바로 정답이 나와서 편하다는 느낌이 먼저 들었다 — 이게 왜 문제인지 바로 와닿지 않았다.

#### 해결 과정
🟢 되돌린 뒤 같은 질문을 다시 던져서 두 답을 나란히 놓고 비교하니, 규칙이 있을 때만 "내가 먼저 시도해보게" 만든다는 차이가 분명하게 보였다.

#### 배운 점
💡 규칙 세 덩이를 빼면 답은 편해지지만 그만큼 내가 생각할 기회가 사라진다 — 편한 것과 도움이 되는 것은 다르다.

#### 확인 체크리스트
- [ ] 규칙을 지운 뒤 답과 되돌린 뒤 답을 각각 적었다
- [ ] 되돌린 뒤 `git status`가 clean이다
- [ ] `/clear` 후 다시 물으면 또 되묻는다 (완성본이 돌아왔다는 뜻)

### 4. /note description 한 줄로 자동 호출되게 만들기

#### 문제 상황
`/note`의 description 한 줄만 고쳐서, 슬래시를 안 쳐도 Claude가 알아서 note 스킬을 부르게 만든다. 고친 뒤 `/clear`하고 `/note`를 치지 않고 "오늘 배운 거 정리해서 블로그에 올려줘"라고만 말해본다.

#### 시도한 방법
```
description: ____________________________________
```
언제 쓰는 것인지 · 어떤 말을 들었을 때 쓰는 것인지를 담아 고친다.

#### 막혔던 점
🔴 처음 고친 description이 "블로그 글을 정리하는 스킬"처럼 짧아서, 실제로 "오늘 배운 거 정리해서 블로그에 올려줘"라고 말했는데도 스킬이 안 불렸다.

#### 해결 과정
🟢 내가 실제로 칠 법한 말("오늘 배운 거", "블로그에 올려줘")을 description 문장 안에 그대로 넣어 다시 고치니 슬래시 없이도 note 스킬이 불렸다.

#### 배운 점
💡 description은 Claude가 "언제 이 스킬을 쓸지" 판단하는 근거다 — 내가 실제로 쓰는 표현이 그 안에 들어 있어야 알아본다.

---

### 5. /note 순서에 단계 하나 더 넣기

#### 문제 상황
`/note`의 순서(SKILL.md 본문 번호 목록)에 단계를 하나 더 넣는다. 예: "글을 쓰기 전에 제목 후보를 3개 보여주고 내가 고르게 해줘". 넣은 뒤 실제로 돌려서 그 단계가 그 자리에서 실행되는지 본다.

#### 시도한 방법
```
1. 먼저 나에게 물어봐 — "뭘 배웠어요?"
2. ____________________________
3. 내 답을 가지고 _posts/ 에 글을 만들어줘. ...
```
번호를 다시 매기는 것을 잊지 않는다.

#### 막혔던 점
🔴 파일만 고친 것이라 재시작이 필요 없다는 걸 몰라서, 처음엔 `/exit` 후 다시 켜야 하나 고민했다.

#### 해결 과정
🟢 저장하자마자 `/clear` → `/note`만으로 새 단계가 그 자리에서 바로 실행되는 걸 확인했다 — 폴더를 새로 만든 게 아니라 재시작이 필요 없었다.

#### 배운 점
💡 재시작은 폴더를 새로 만들 때만 필요하다. 기존 파일을 고친 건 저장하는 즉시 반영된다.

### 6. AI 없이 규칙 세 개에서 빠진 것 고르기

#### 문제 상황
AI를 켜지 않고 푸는 문제다. 지침 세 개를 읽고 각각 방어·성장·탈출구·경계 중 무엇이 빠졌는지 고른다.

```
지침 ① — 답부터 주지 말고 되물어줘 / 답 대신 다음 한 걸음만 / "힌트 끝까지 줘"하면 전부
지침 ② — 확실하지 않으면 모른다고 말해, 지어내지 마 / 답이 하나뿐인 건 바로 알려줘
지침 ③ — 소크라테스식으로 교육적으로 답해줘 / 내가 성장할 수 있게 도와줘
```

#### 시도한 방법
각 지침에서 있는 것과 빠진 것을 표시한다.
```
지침 ① — 있는 것: 성장, 탈출구 / 빠진 것: ____
지침 ② — 있는 것: ____ / 빠진 것: ____
지침 ③ — 있는 것: ____ / 진짜 문제: ____
```

#### 막혔던 점
🔴 지침 ③은 겉보기엔 "성장"이 있는 것처럼 보여서 빠진 게 없다고 판단할 뻔했다.

#### 해결 과정
🟢 "이 문장을 읽고 AI가 무엇을 할지 한 가지로 정해지는가"를 기준으로 다시 보니, ③은 빠진 항목의 문제가 아니라 문장 자체가 추상적이어서 애초에 판정이 안 된다는 걸 알았다.

#### 배운 점
💡 지침 ①은 방어(경계)가 빠졌고, ②는 성장·탈출구가 빠졌고, ③은 빠진 항목의 문제가 아니라 "소크라테스식으로"·"교육적으로" 같은 추상적 표현이 애초에 동작으로 안 번역된다는 게 진짜 문제였다.

## Lv.1 여섯 문제를 풀어보고 나서

여섯 문제 중 가장 헷갈렸던 건 2번(성장 규칙 추가)과 6번(빠진 것 고르기)이었다. 둘 다 "문장이 얼마나 구체적인가"가 판정 기준이라는 걸 알기 전까지는 뭘 고쳐야 할지 감이 안 잡혔다. `/learn`은 Lv.1을 풀면서 역할 한 줄, 규칙 한 줄을 각각 고쳤고, 3번에서 규칙 세 덩이를 지웠다가 되돌린 것까지 치면 총 세 번 손을 댄 셈이다.

## 더 학습하면 좋은 개념

- **Claude Code Agent Skills 공식 가이드** — description 필드가 어떻게 스킬 호출을 트리거하는지(4번 문제), `SKILL.md` 구조 전반을 공식 문서로 확인해두면 스킬을 늘려갈수록 도움이 된다.
- **프롬프트 엔지니어링 — System Prompts (역할·규칙 분리)** — "역할"과 "규칙"을 다른 칸으로 나눠 쓰는 감각(1·2번 문제)은 시스템 프롬프트를 역할·규칙·형식으로 나누는 공식 가이드와 이어진다.
- **git restore vs git revert** — 3번 문제에서 커밋 전 상태로 되돌릴 때 쓴 `restore`는, 이미 커밋된 것을 되돌릴 때 쓰는 `revert`와 다르다. 상황별로 구분해두면 스킬 실험을 더 과감하게 할 수 있다.
- **Few-shot / 예시 기반 프롬프트** — 규칙 문장이 추상적이면 안 먹힌다는 것(2·6번 문제)의 다음 단계로, 문장 대신 예시를 보여주면 더 안정적으로 지켜지는 경우가 많다.
