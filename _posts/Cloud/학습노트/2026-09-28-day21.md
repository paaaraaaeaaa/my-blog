# 오늘 배운 것: byte 오버플로우가 127+1을 -128로 순환시키는 이유

## 들어가며 (Situation)

Java 개발자 부트캠프 1모듈에서 Java 언어의 기초 문법을 다루는 첫날이었다. 지금까지는 Git·GitHub·HTML/CSS 위주로 진행했는데, 오늘부터 본격적으로 Java 언어 자체를 학습하기 시작했다.

먼저 JDK 21을 설치하고 `java -version`으로 설치를 확인했다. 그 다음 IntelliJ에서 New Project로 첫 Java 프로젝트(`chap01-java-basic`)를 만들었고, 이후 리터럴·변수·상수·오버플로우·형변환·연산자를 순서대로 학습했다.

## 문제 상황 (Task)

학습 자료 마지막에 다음과 같은 생각해보기 문제가 있었다.

```java
byte bnum = 127;
bnum++;
System.out.println(bnum);
```

`byte`의 최댓값인 127에 1을 더했으니 128이 나올 것 같지만, 실제로는 다른 값이 출력된다. **왜 이런 결과가 나오는지**를 `byte`, `bit`, `overflow`, `underflow`, `type casting` 키워드를 포함해서 설명해야 했다.

## 해결 과정 (Action)

### 1. 기본 자료형부터 정리

`byte`는 1바이트(8비트)를 할당받는 정수형 자료형이고, 표현 범위는 -128 ~ 127이다.

| 타입 | 크기 | 표현 범위 |
| --- | --- | --- |
| `byte` | 1바이트 | -128 ~ 127 |
| `short` | 2바이트 | -32,768 ~ 32,767 |
| `int` | 4바이트 | -2,147,483,648 ~ 2,147,483,647 |
| `long` | 8바이트 | -9,223,372,036,854,775,808 ~ 9,223,372,036,854,775,807 |

### 2. 부호 비트가 핵심이었다

💡 `byte`의 8비트 중 맨 앞 1비트는 **부호 비트(sign bit)**로 쓰인다. `0`이면 양수, `1`이면 음수를 뜻한다. 그래서 실제 값으로 쓸 수 있는 비트는 7비트뿐이라 양수 쪽 최댓값이 `2^7 - 1 = 127`인 것이다.

여기서 헷갈렸던 부분은 "그럼 음수도 127개, 양수도 127개 아닌가?"였는데, 직접 표를 그려보면서 이유를 정리했다.

- **0은 양수 쪽에 포함된다**
  - `0000 0000`이 0을 나타내므로, 양수 쪽은 0~127까지 **128개** 값을 쓰는 것 같지만, 실제로는 0을 제외한 1~127이 양수이고 0은 별도다.
  - 결국 표현 범위는 음수 -128~-1(128개) + 0(1개) + 양수 1~127(127개) = 총 256개(2^8)가 딱 맞아떨어진다.
- **음수의 최솟값이 -128인 이유**
  - 자바는 음수를 **2의 보수(two's complement)** 방식으로 표현한다. 이 방식에서는 `1000 0000`이 -128을 나타내는데, 이 비트 패턴에 대응하는 양수 값이 별도로 존재하지 않기 때문에 음수 쪽이 양수 쪽보다 표현 가능한 값이 1개 더 많다.

### 3. 127에 1을 더하면 실제로 무슨 일이 일어나는가

`127`은 비트로 `0111 1111`이다. 여기에 1을 더하면 비트 연산상 `1000 0000`이 되는데, 이 비트 패턴은 부호 비트가 `1`이므로 **-128**로 해석된다.

```java
byte bnum = 127;   // 0111 1111
bnum++;             // 1000 0000 → 부호 비트가 1이라 -128로 해석됨
System.out.println(bnum);
```

🟢 즉, 8비트로 표현할 수 있는 범위(256가지)를 넘어서는 순간 **캐리(carry)가 버려지고 부호 비트가 반전되면서 최솟값으로 되돌아가는 것**이 오버플로우다. `byte`는 딱 -128~127 범위 안에서 이 과정을 반복한다.

### 4. "음수가 무한히 나온다"는 오해를 바로잡았다

처음에는 `bnum++`을 계속 실행하면 음수가 끝없이 새로 나올 거라고 생각했는데, 그렇지 않다. `byte`는 여전히 8비트, 즉 -128~127이라는 **고정된 범위 안에서 순환(wrap-around)**할 뿐이다.

```text
127 → -128 → -127 → -126 → ... → -1 → 0 → 1 → ... → 127 → -128 → ...
```

🔴 "오버플로우 = 값이 무한히 커지거나 작아진다"고 생각하면 틀린다. 실제로는 **정해진 비트 수 안에서 값이 순환**하는 것이라서, `byte`에 아무리 증가 연산을 반복해도 결국 -128~127 안의 값만 나온다.

### 5. underflow와 type casting은 어떻게 연결되는가

- **underflow**는 오버플로우와 반대 방향이다. `byte`의 최솟값 -128에서 1을 빼면(`bnum--`), 비트가 `1000 0000`에서 `0111 1111`로 바뀌면서 다시 127로 순환한다.
- **type casting(형변환)**은 오버플로우를 막는 실질적인 해결책이다. 예를 들어 `int`끼리 곱해서 `int` 범위를 넘는 결과가 예상된다면, 연산 전에 미리 `long`으로 강제 형변환해서 계산해야 한다.
  ```java
  int firstNum = 1000000;
  int secondNum = 700000;

  long result = (long) firstNum * secondNum; // 계산 전에 형변환해야 오버플로우 방지
  System.out.println(result); // 700000000000
  ```
  ⚠️ 곱셈 결과를 `long` 변수에 담기만 하고 계산 자체는 `int`끼리 했다면(`long longMulti = firstNum * secondNum;`), 이미 `int` 범위에서 오버플로우가 발생한 뒤이므로 여전히 잘못된 값이 나온다. **형변환은 연산이 일어나기 전에** 해야 의미가 있다.

## 결과 (Result)

- `byte bnum = 127; bnum++;`의 결과가 **-128**이라는 것을, "값이 넘친다"는 추상적인 설명이 아니라 **부호 비트가 반전되는 비트 연산 과정**으로 설명할 수 있게 되었다.
- "오버플로우가 반복되면 음수가 무한히 생긴다"는 잘못된 이해를, "고정된 비트 범위 안에서 순환한다"로 바로잡았다.
- 형변환이 오버플로우 대책이 되려면 **연산 전에** 적용해야 한다는 것을 실제 코드 예제로 확인했다.

## 더 학습하면 좋은 개념

- **2의 보수(Two's Complement)** — 오늘 다룬 부호 비트와 오버플로우를 제대로 이해하려면, 컴퓨터가 음수를 어떻게 비트로 표현하는지(2의 보수 연산)를 알아야 한다. 뺄셈을 덧셈으로 처리하는 원리도 여기서 나온다.
- **IEEE 754 부동소수점 표준** — `float`/`double` 연산에서 `0.229999...` 같은 오차가 왜 생기는지는 부동소수점이 실수를 가수·지수로 나눠 저장하는 방식(IEEE 754)을 알아야 설명할 수 있다.
- **비트 연산자(`&`, `|`, `^`, `<<`, `>>`, `>>>`)** — 오늘은 오버플로우를 비트 관점에서 봤는데, 실제로 비트를 직접 조작하는 연산자를 배우면 오늘 이해한 내용을 코드로 검증해볼 수 있다.
- **정수 오버플로우 방지 기법** — 실무에서는 `Math.addExact()`처럼 오버플로우 발생 시 예외를 던지는 API를 쓰기도 한다. 형변환 외에 어떤 안전장치가 있는지 찾아보면 좋다.
