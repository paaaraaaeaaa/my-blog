# 오늘 배운 것: 자바 기초 문법 첫날 — 리터럴부터 연산자, byte 오버플로우까지

## 들어가며 (Situation)

Java 개발자 부트캠프 모듈 2 첫날이었다. 지금까지는 Git·GitHub·HTML/CSS 위주였는데, 오늘부터 Java 언어 자체를 배우기 시작했다.

먼저 JDK/JRE/JVM 구조와 자바 코드 실행 원리를 배우고 JDK 21을 설치한 뒤 `java -version`으로 설치를 확인했다. 그 다음 IntelliJ에서 New Project로 첫 Java 프로젝트(`chap01-java-basic`)를 만들었고, 이후 두 개의 학습 자료를 통해 ① 리터럴·변수·상수·오버플로우·형변환, ② 연산자 전반을 학습했다.

## 문제 상황 (Task)

오늘 다뤄야 할 범위가 꽤 넓었다.

- JDK·JRE·JVM의 관계와 자바 코드가 실행되는 원리(컴파일 → 바이트코드 → JVM)
- 리터럴 6종류(논리·정수·실수·문자·문자열)와 기본 자료형 8가지의 메모리 크기·표현 범위
- 변수·상수의 선언/초기화 방법과 명명 규칙
- 오버플로우·언더플로우가 발생하는 원리, 자동/강제 형변환의 조건
- 산술·대입·증감·비교·논리·삼항 연산자 각각의 동작과 우선순위

그중에서도 학습 자료 마지막에 나온 다음 문제가 가장 핵심적인 과제였다.

```java
byte bnum = 127;
bnum++;
System.out.println(bnum);
```

`byte`의 최댓값 127에 1을 더했으니 128이 나올 것 같지만 실제로는 다른 값이 출력된다. `byte`, `bit`, `overflow`, `underflow`, `type casting` 키워드를 포함해서 **왜 이런 결과가 나오는지**를 설명해야 했다.

## 해결 과정 (Action)

### 1. JDK·JRE·JVM — 자바 코드가 실행되는 원리

- **JDK(Java Development Kit)**
  - JRE에 `javac`(컴파일러) 같은 개발 도구를 더한 것. 프로그램을 **만들려면** JDK가 필요하다.
- **JRE(Java Runtime Environment)**
  - 자바 프로그램을 **실행**만 하는 환경. 클래스 로더·바이트코드 검증기·실행 엔진·메모리 관리 기능을 담고 있다.
- **JVM(Java Virtual Machine)**
  - 바이트코드(`.class`)를 읽어서 지금 이 컴퓨터(Windows, macOS 등)가 알아듣는 기계어로 바꿔 실행하는, 내 컴퓨터 안의 '자바 전용 가상 컴퓨터'.

💡 우리는 JDK 하나만 설치하면 된다. JDK 안에 JRE와 JVM이 모두 들어 있어서, 코드를 작성할 수도 있고 실행할 수도 있다.

**왜 하필 JDK 21인가**도 짚고 넘어갔다. 자바는 2018년부터 6개월마다 새 버전이 나오는데, 그중 일부만 **LTS(장기 지원)** 버전으로 지정해 몇 년간 보안·버그 수정을 이어간다.

- 오래 지원받는 LTS라 배운 환경 그대로 실제 프로젝트까지 안심하고 쓸 수 있다.
- 모듈 2에서 쓸 최신 Spring Boot가 Java 17 이상을 요구하는데, 21은 이 조건을 넉넉히 채우고 현업에서도 널리 쓰인다.
- 최신 LTS는 25지만, 21은 자료·라이브러리·회사 사례가 충분히 쌓여 있고 21에서 배운 문법은 25에서도 그대로 동작한다.

자바의 원본 소스는 오픈소스 프로젝트 **OpenJDK**에 공개되어 있고, 여러 회사가 같은 원본으로 배포판을 만든다(Eclipse Temurin, Oracle JDK, Amazon Corretto 등). 수업에서는 그중 **Eclipse Temurin**을 설치했다.

**자바 코드가 실행되는 과정**은 두 번의 번역을 거친다.

1. **컴파일 타임(개발자 컴퓨터에서 한 번)**: `javac Hello.java`를 실행하면 컴파일러가 문법 오류를 검사하고, 문제가 없으면 **바이트코드**(`Hello.class`)로 번역한다.
2. **런타임(실행할 때마다)**: JVM이 바이트코드를 검증(바이트코드 검증기)한 뒤, 인터프리터가 한 줄씩 기계어로 통역해 실행한다. 같은 코드가 자주 반복되면 **JIT(Just-In-Time) 컴파일러**가 그 부분을 통째로 기계어로 번역해 저장해두고, 다음부터는 바로 실행해서 빨라진다.

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

```text
javac Hello.java   # 컴파일: Hello.java → Hello.class(바이트코드)
java Hello          # 실행: JVM이 Hello.class를 읽어 기계어로 통역
```

🟢 바이트코드는 특정 CPU가 아니라 **JVM을 위한 명령어**다. 그래서 Windows에서 만든 `Hello.class` 하나를 Mac이나 Linux로 그대로 가져가도, 그 컴퓨터의 JVM이 자기 CPU에 맞는 기계어로 통역해준다 — **"한 번 작성하면, 어디서나 실행(Write Once, Run Anywhere)"**의 원리다. 대신 C 같은 언어와 달리, 실행하는 컴퓨터마다 그 운영체제용 JVM이 설치되어 있어야 한다. 오늘 JDK를 설치한 이유가 바로 이것이다.

### 2. 리터럴(literal) — 데이터 그 자체

- **리터럴(literal)**
  - 변하지 않는 데이터 그 자체를 말한다. 저장 공간을 뜻하는 상수(constant)와는 다른 개념이다.
  - `int age = 20;`에서 `20`이 리터럴이고, `age`가 그 값을 담는 변수다.

| 종류 | 예시 | 접두사/접미사 |
| --- | --- | --- |
| 논리형 | `false`, `true` | - |
| 정수형 | `100`, `0b0011`, `077`, `0xFF`, `12L` | `L`(long), `0`(8진수), `0x`(16진수) |
| 실수형 | `3.14`, `12.0e8`, `7.7f` | `f`(float), `d`(double, 생략 가능) |
| 문자형 | `'O'`, `'1'`, `'\n'` | - |
| 문자열 | `"text"`, `"100"`, `"false"` | - |

숫자 리터럴 연산에서 가장 인상 깊었던 건, **정수와 실수를 연산하면 항상 실수로 나온다**는 점과 문자열 이어붙이기다.

```java
System.out.println(9 + 9 + "9");   // 189 — 정수끼리 먼저 계산 후 문자열 결합
System.out.println(9 + "9" + 9);   // 999 — 앞에서부터 순서대로 문자열 결합
System.out.println("9" + (9 + 9)); // 918 — 괄호로 우선순위를 바꿈
```

⚠️ `System.out.println("결과: " + 10 + 20)`처럼 괄호 없이 쓰면 `10`, `20`이 각각 문자열로 이어붙는다. 계산 결과를 문자열에 넣고 싶으면 `(10 + 20)`처럼 반드시 괄호로 묶어야 한다.

### 3. 변수(variable)와 자료형

- **변수(variable)**
  - 데이터를 저장하기 위해 할당받은 메모리 공간. 선언(declare) → 값 대입(assign) → 초기화(initialization) 순서로 사용한다.
- **자료형(data type)**
  - 값의 크기를 컴파일러와 미리 약속해둔 키워드. 기본자료형(Primary type)과 참조자료형(Reference type)으로 나뉜다.

| 타입 | 크기 | 표현 범위 |
| --- | --- | --- |
| `byte` | 1바이트 | -128 ~ 127 |
| `short` | 2바이트 | -32,768 ~ 32,767 |
| `int` | 4바이트 | -2,147,483,648 ~ 2,147,483,647 |
| `long` | 8바이트 | -9,223,372,036,854,775,808 ~ 9,223,372,036,854,775,807 |
| `float` | 4바이트 | 3.4×10⁻³⁸ ~ 3.4×10³⁸ |
| `double` | 8바이트 | 1.7×10⁻³⁰⁸ ~ 1.7×10³⁰⁸ |
| `char` | 2바이트 | 0 ~ 65,535 (부호 비트 없음) |
| `boolean` | 1바이트 | `true` / `false` |

변수 명명 규칙 중 실무에서 특히 신경 써야겠다고 느낀 부분을 정리했다.

- **컴파일 에러가 나는 규칙**
  - 같은 범위 안에서 이름 중복 불가, 예약어 사용 불가, 대소문자 구분, 숫자로 시작 불가, 특수기호는 `_`와 `$`만 가능.
- **암묵적 규칙(camelCase 등)**
  - 첫 단어는 소문자·이후 단어는 대문자로 시작(`memberAddress`), 언더스코어 연결 지양, `boolean`은 긍정형 의문문으로 네이밍(`isAlive`).

### 4. 상수(constant) — 값을 바꿀 수 없는 저장 공간

- **상수(constant)**
  - 변수처럼 데이터를 저장하지만, 한 번 초기화하면 값을 바꿀 수 없다. `final` 키워드를 자료형 앞에 붙여 선언한다.
  - 명명 규칙은 변수와 반대로 **대문자 + 언더스코어**(`MAX_AGE`)를 쓴다.
  - 수학 공식 상수나 DB 접속 정보처럼 변하면 안 되는 값을 저장할 때 쓴다.

```java
final int AGE;
AGE = 20;
// AGE = 30;  // 초기화 이후 재대입은 컴파일 에러
```

### 5. 오버플로우(overflow) — byte 문제를 비트로 파고들기

💡 오버플로우란 자료형이 담을 수 있는 값의 범위를 벗어났을 때, 넘친 비트(캐리)는 버려지고 부호 비트가 반전되면서 값이 최소값으로 되돌아가는 현상이다.

`byte`의 8비트 중 맨 앞 1비트는 **부호 비트(sign bit)**다. `0`이면 양수, `1`이면 음수를 뜻하고, 실제 값으로 쓸 수 있는 비트는 7비트뿐이라 양수 쪽 최댓값이 `2^7 - 1 = 127`이다.

여기서 헷갈렸던 건 "그럼 음수도 127개, 양수도 127개 아닌가?"였는데, 직접 비트를 그려보며 정리했다.

- 자바는 음수를 **2의 보수(two's complement)**로 표현하는데, `1000 0000`이라는 비트 패턴은 -128을 나타내고 이에 대응하는 별도의 양수 값이 없다.
- 그래서 음수 -128~-1(128개) + 0(1개) + 양수 1~127(127개) = 256개(2⁸)가 정확히 맞아떨어지고, 음수 쪽이 양수 쪽보다 표현 가능한 값이 1개 더 많다.

`127`은 비트로 `0111 1111`이다. 여기에 1을 더하면 `1000 0000`이 되는데, 이 패턴은 부호 비트가 `1`이라 **-128**로 해석된다.

```java
byte bnum = 127;   // 0111 1111
bnum++;             // 1000 0000 → 부호 비트가 1이라 -128로 해석됨
System.out.println(bnum);
```

🔴 처음엔 `bnum++`을 계속하면 음수가 끝없이 새로 나올 거라 생각했는데, 이건 틀렸다. `byte`는 여전히 8비트, 즉 -128~127이라는 **고정된 범위 안에서 순환(wrap-around)**할 뿐이다.

```text
127 → -128 → -127 → -126 → ... → -1 → 0 → 1 → ... → 127 → -128 → ...
```

🟢 "오버플로우 = 값이 무한히 커지거나 작아진다"가 아니라, **정해진 비트 수 안에서 값이 순환**하는 것이다. `byte`는 아무리 증가 연산을 반복해도 결국 -128~127 안의 값만 나온다.

**underflow**는 반대 방향이다. `byte`의 최솟값 -128에서 1을 빼면(`bnum--`), 비트가 `1000 0000`에서 `0111 1111`로 바뀌면서 다시 127로 순환한다.

### 6. 형변환(type casting) — 오버플로우를 막는 실질적인 방법

- **자동 형변환(묵시적)**
  - 작은 자료형 → 큰 자료형, 정수 → 실수, 문자 → int처럼 데이터 손실 가능성이 없을 때 컴파일러가 자동으로 처리한다.
- **강제 형변환(명시적)**
  - 큰 자료형 → 작은 자료형, 실수 → 정수처럼 데이터 손실 가능성이 있을 때 `(자료형)` 연산자로 직접 지정해야 한다.

오버플로우와 형변환을 연결해서 이해한 부분이 특히 중요했다.

```java
int firstNum = 1000000;
int secondNum = 700000;

// long longMulti = firstNum * secondNum;
// → int끼리 곱한 뒤 결과를 long에 담아도 이미 오버플로우가 발생한 뒤라 여전히 틀린 값

long result = (long) firstNum * secondNum; // 연산 전에 형변환해야 오버플로우 방지
System.out.println(result); // 700000000000
```

⚠️ 형변환은 **연산이 일어나기 전에** 해야 의미가 있다. 계산이 끝난 뒤 결과를 큰 자료형 변수에 담기만 하면, 이미 작은 자료형 범위에서 오버플로우가 발생한 뒤라 소용이 없다.

### 7. 연산자(operator) — 산술부터 삼항까지

| 종류 | 연산자 | 설명 |
| --- | --- | --- |
| 산술 연산자 | `+`, `-`, `*`, `/`, `%` | 사칙연산과 나머지 |
| 대입 연산자 | `=`, `+=`, `-=`, `*=`, `/=`, `%=` | 오른쪽 값을 왼쪽에 대입 |
| 증감 연산자 | `++`, `--` | 피연산자를 1 증가/감소시키는 단항 연산자 |
| 비교 연산자 | `>`, `<`, `>=`, `<=`, `==`, `!=` | 두 값의 상대적 크기 비교 |
| 논리 연산자 | `&&`, `||`, `!` | 논리식을 판단해 true/false 반환 |
| 삼항 연산자 | `? :` | 피연산자가 3개인 유일한 연산자 |

- **증감 연산자의 위치 차이**
  - `++var`(전위): 먼저 증가시킨 뒤 다른 연산을 진행한다.
  - `var++`(후위): 다른 연산을 먼저 진행하고 마지막에 증가시킨다.

```java
int firstNum = 20;
int result1 = firstNum++ * 3; // firstNum(20)으로 먼저 곱하고 나중에 증가 → 60
System.out.println(result1 + " / " + firstNum); // 60 / 21

int secondNum = 20;
int result2 = ++secondNum * 3; // 먼저 21로 증가시킨 뒤 곱함 → 63
System.out.println(result2 + " / " + secondNum); // 63 / 21
```

- **논리 연산자의 단축 평가(short-circuit)**
  - `&&`는 앞이 `false`면 뒤를 실행하지 않고, `||`는 앞이 `true`면 뒤를 실행하지 않는다.
  - 그래서 `&&`는 false가 나올 가능성이 높은 조건을, `||`는 true가 나올 가능성이 높은 조건을 앞에 두면 연산 횟수를 줄일 수 있다.

```java
int num1 = 10;
int result = (false && ++num1 > 0) ? num1 : num1; // 앞이 false라 ++num1 실행 안 됨
System.out.println(result); // 10 (11이 아님)
```

- **문자열 비교는 `==`가 아니라 `equals()`**
  - `==`는 문자열이 저장된 주소값을 비교하는 것이라, 값 자체를 비교하려면 `문자열.equals(비교할문자열)`을 써야 한다. (자세한 원리는 자주 쓰는 API 챕터에서 다룰 예정)

## 결과 (Result)

- JDK·JRE·JVM의 역할 차이와 `javac`(컴파일) → 바이트코드(`.class`) → JVM(실행)으로 이어지는 자바 실행 과정을 설명할 수 있게 되었다.
- 리터럴 6종류, 기본 자료형 8가지, 연산자 6종류(산술·대입·증감·비교·논리·삼항)를 표로 정리해 하루 만에 훑을 수 있는 참고 자료를 만들었다.
- `byte bnum = 127; bnum++;`의 결과가 **-128**인 이유를, "값이 넘친다"는 추상적인 설명이 아니라 **부호 비트가 반전되는 비트 연산 과정**으로 설명할 수 있게 되었다.
- "오버플로우가 반복되면 음수가 무한히 생긴다"는 잘못된 이해를, "고정된 비트 범위 안에서 순환한다"로 바로잡았다.
- 형변환이 오버플로우 대책이 되려면 **연산 전에** 적용해야 한다는 것을 코드로 직접 확인했다.

## 더 학습하면 좋은 개념

- **2의 보수(Two's Complement)** — 오늘 다룬 부호 비트와 오버플로우를 제대로 이해하려면, 컴퓨터가 음수를 어떻게 비트로 표현하는지(2의 보수 연산)를 알아야 한다. 뺄셈을 덧셈으로 처리하는 원리도 여기서 나온다.
- **IEEE 754 부동소수점 표준** — `float`/`double` 연산에서 `0.229999...` 같은 오차가 왜 생기는지는 부동소수점이 실수를 가수·지수로 나눠 저장하는 방식(IEEE 754)을 알아야 설명할 수 있다.
- **비트 연산자(`&`, `|`, `^`, `<<`, `>>`, `>>>`)** — 오늘은 오버플로우를 비트 관점에서 봤는데, 실제로 비트를 직접 조작하는 연산자를 배우면 오늘 이해한 내용을 코드로 검증해볼 수 있다.
- **String.equals()와 문자열 풀(String Pool)** — 오늘 잠깐 짚은 `==` vs `equals()` 차이는 자바의 문자열 저장 방식을 알아야 완전히 이해된다.
- **정수 오버플로우 방지 기법** — 실무에서는 `Math.addExact()`처럼 오버플로우 발생 시 예외를 던지는 API를 쓰기도 한다. 형변환 외에 어떤 안전장치가 있는지 찾아보면 좋다.
- **JVM 메모리 구조(Stack, Heap, Method Area)** — 오늘은 바이트코드가 JVM에서 실행되는 흐름만 봤는데, 변수와 객체가 실제로 JVM의 어느 메모리 영역에 저장되는지 알면 오늘 배운 실행 원리가 한층 더 명확해진다.
