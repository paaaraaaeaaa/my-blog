# 서버를 띄우고(포트만 18088로 바꿈) 브라우저 대신 파이썬 스크립트로 요청을 보낸 결과다. 리다이렉트는 따라가지 않고 상태 코드와 Location 만 적었다.
# `login` DB 의 실제 회원 데이터가 바뀌지 않게, 실행은 menudb 에 TBL_USER, TBL_LOGIN_LOG 와 같은 모양의 임시 테이블을 만들어 거기에 연결했다.
#   (User, LoginLog 의 @Table 이름과 DB 주소만 바꾼 복사본. 아래에는 읽기 쉽게 원래 테이블 이름으로 적었고, 임시 테이블은 확인 뒤 지웠다.)
# 쿠키 값은 <값> 으로 가렸다. 요청마다 새 "브라우저"(쿠키 저장소)를 만들어 보냈다.
# 서버 로그의 SQL 은 시간이 조금 어긋나게 찍히는 경우가 있어서, 개수를 적은 곳은 DB 값과 코드로 맞춰 본 것만 적었다.

===== A. 로그인 전 접근 (익명)
GET /               -> 200
GET /auth/login     -> 200
GET /user/page      -> 302 Location /auth/login   (이때 JSESSIONID 쿠키가 만들어진다)
GET /admin/logs     -> 302 Location /auth/login
GET /method/admin   -> 302 Location /auth/login

===== B. 회원가입
POST /user/signup  userId=user1 userPass=**** role=USER   -> 200
  SQL: select ... from tbl_user where user_id=? limit ?
  SQL: insert into tbl_user (is_account_locked, login_fail_count, password, user_id, user_name, user_role) values (?, ?, ?, ?, ?, ?)
POST /user/signup  (같은 아이디 다시)                     -> 200, 화면 메시지 "중복회원이 존재합니다."
  SQL: select ... from tbl_user where user_id=? limit ?   (insert 없음)
POST /user/signup  userId=admin1 userPass=**** role=ADMIN -> 200
DB: user1  | USER  | 비밀번호 길이 60 | 앞 7글자 $2a$10$ | 실패 0 | 잠금 0
DB: admin1 | ADMIN | 비밀번호 길이 60 | 앞 7글자 $2a$10$ | 실패 0 | 잠금 0
같은 비밀번호(두 계정 모두 같은 값)인데 서로 다른 해시의 개수: 2

===== C. 로그인 실패
POST /auth/login  user=nouser pass=x    -> 302 Location /auth/fail?message=아이디가 존재하지 않거나 비밀번호가 일치하지 않습니다. (실패 횟수: 누적)
  SQL: select ... from tbl_user where user_id=?   (두 번: 로그인 조회, 실패 핸들러의 횟수 증가 조회)
  SQL: insert into tbl_login_log (ip_address, login_time, success, user_id) values (?, ?, ?, ?)
POST /auth/login  user=user1 pass=wrong -> 302 Location /auth/fail?message=아이디가 존재하지 않거나 비밀번호가 일치하지 않습니다. (실패 횟수: 누적)
  SQL: select ... (두 번)
  SQL: update tbl_user set is_account_locked=?, login_fail_count=?, password=?, user_id=?, user_name=?, user_role=? where user_no=?
  SQL: insert into tbl_login_log (...) values (...)
DB: user1 실패 1 / admin1 실패 0
(두 번 더 틀림) DB: user1 실패 3, 잠금 0
GET /auth/fail?message=...  -> 200, 화면 메시지: 아이디가 존재하지 않거나 비밀번호가 일치하지 않습니다. (실패 횟수: 누적)
로그인 로그: nouser 실패, user1 실패 x3, IP 는 모두 0:0:0:0:0:0:0:1

===== C-2. 실패 3번 뒤 맞는 비밀번호
POST /auth/login  user=user1 pass=****  -> 302 Location /      (Set-Cookie: JSESSIONID)
  SQL: select (조회) / select (횟수 초기화 조회) / update (실패 횟수 3 -> 0) / insert 로그
DB: user1 실패 0, 잠금 0
로그인 로그: user1 성공

GET /admin/page   -> 403
GET /method/admin -> 200     (아직 @EnableMethodSecurity, @PreAuthorize 가 TODO 라서 USER 도 통과)

===== C-4. 로그아웃
POST /auth/logout -> 302 Location /
  Set-Cookie: JSESSIONID=<값>; Max-Age=0 ...
  Set-Cookie: remember-me=<값>; Max-Age=0 ...  (두 번 내려온다)
GET /user/page    -> 302 Location /auth/login
(다시 로그인한 뒤) GET /auth/logout -> 302 Location /      <- POST 가 아니라 GET 으로도 로그아웃된다 (CSRF 보호를 꺼 둔 상태)
GET /user/page    -> 302 Location /auth/login

===== D. 계정 잠금 (user2 로 틀린 비밀번호를 반복)

  SQL: select (조회 한 번) / insert 로그      (update 없음)
  DB: user2 실패 5, 잠금 1                    <- 잠긴 뒤에는 횟수가 늘지 않는다

===== F. 로그인 전에 가려던 페이지
GET /user/page    -> 302 Location /auth/login   (로그인 전, JSESSIONID 쿠키를 받는다)
POST /auth/login  user=user1 pass=****  -> 302 Location /      <- 가려던 /user/page 가 아니라 "/" 로 이동

===== G. Remember Me
POST /auth/login  user=user1 pass=**** remember-me=on -> 302 Location /
  Set-Cookie: JSESSIONID=<값>; Path=/; HttpOnly
  Set-Cookie: remember-me=<값>; Max-Age=86400; Expires=(24시간 뒤); Path=/; HttpOnly
JSESSIONID 없이 remember-me 쿠키만 보내서 GET /user/page -> 200   (새 JSESSIONID 가 내려온다)
같은 쿠키로 한 번 더 GET /user/page -> 200
DB 의 user1 성공 로그는 로그인한 횟수와 같다. (Remember Me 자동 로그인은 성공 로그를 쌓지 않았다)
