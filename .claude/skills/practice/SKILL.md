# 문제풀이 devlog 만들기

사용자가 `/practice`와 함께 문제 링크를 준다: $ARGUMENTS

아래 순서대로 해줘.

1. 링크를 열어서 문제 내용을 전부 읽는다. 한 번에 다 안 열리면(스크롤·펼치기 필요, 로그인 필요, 이미지라 못 읽음 등) 읽을 수 있는 만큼 읽고 부족한 부분을 알려줘 — 이건 "뭘 배웠어요?" 같은 질문이 아니라 "이 뒷부분이 안 열려요, 캡처해서 보내줄래요?" 같은 정보 확인 질문이다. 이 확인이 필요 없으면 묻지 말고 바로 진행한다.
2. 아래 두 가지가 애매하면만 짧게 확인한다.
   - 개인 미션인지 팀 미션인지, 팀이면 우리 팀이 배정된 미션이 뭔지
   - 문제가 여러 개일 때 전부 다루는지 일부만 다루는지
3. 문제(또는 미션의 단계)마다 `문제 상황 → 시도한 방법 → 막혔던 점 → 해결 과정 → 배운 점` 순서로 정리한다. 시간(몇 분 걸렸는지)은 적지 않는다.
4. `막혔던 점`/`배운 점`은 실제 경험을 적는 자리다. 아직 안 겪었으면 빈 칸(`> (...)`)으로 남겨도 되고, 자연스러운 초안으로 채워도 된다 — 채웠다면 "이 문단들은 실제 경험으로 바꿔 써야 한다"고 나에게 표시해줘.
5. 아래 이모지를 해당 문단 맨 앞에 붙여서 색 블록으로 구분한다(custom.html에 이미 스타일 있음, 새로 안 만들어도 됨).
   - 🔴 막혔던 점
   - 🟢 해결 과정 / 확인 방법
   - 💡 배운 점 / 핵심 개념
   - ⚠️ 주의할 점 / 막힐 수 있는 지점
### 5.3.1 practice 글 추가 규칙

`type: practice`인 글(문제풀이·자율 실습·팀 미션 devlog 등)에는 아래를 추가로 지킨다.

- **파일 위치**: `_posts/Cloud/문제풀이` 바로 아래에 둔다 (`_posts/Cloud/...`처럼 카테고리 이름의 하위 폴더를 만들지 않는다). 카테고리는 폴더가 아니라 front matter의 `categories: Cloud`로 정한다.
- **`layout`은 쓰지 않는다**: `_config.yml`의 defaults가 모든 글에 `layout: single`을 자동으로 넣는다. 직접 `layout: post`를 쓰면 목차·사이드바·콜아웃 기능이 깨진다.
- **`date`는 하이픈 표기**: `date: YYYY-MM-DD` (예: `2026-08-29`). 점 표기(`2026.08.29`)는 cloud.md의 날짜 필터가 오작동할 수 있다.
- **`topic` 필드 추가**: `topic: "<문제 제목>"`을 채운다. `/cloud/` 페이지의 "🧩 문제풀이" 섹션이 이 값으로 글을 묶어서 보여준다.
- **`level_order` 필드 추가**: 같은 `topic` 안에서 카드 정렬 순서를 정한다(날짜가 같아도 이 값으로 정렬됨). `Lv.1=10`, `Lv.2=20`, `Lv.3=30`, `보너스/추가문제=90`. 한 글에 레벨 두 개를 합쳤으면(예: Lv2+Lv3) 더 낮은 쪽 번호를 쓴다(20). 레벨 구분이 없는 주제(미션 1개 글)는 게시 순서대로 10, 20, 30…으로 채운다.
- **`subtitle`/`excerpt` 필드 추가**: `subtitle`은 글 목록 카드에 제목 아래 소제목으로 그대로 노출된다. `excerpt`는 같은 문구를 넣는다.
- **본문에 `#`(h1) 쓰지 않기**: 큰 구분(예: Lv.1, 미션 이름)은 `##`, 그 안의 개별 문제·단계는 `###`, 하위 항목(문제 상황/시도한 방법/막혔던 점 등)은 `####`로 쓴다. 본문에서 `#`을 쓰면 오른쪽 목차(TOC)의 들여쓰기가 깨진다.
- **시간 기록 금지**: "15분", "25분"처럼 문제별 소요 시간은 적지 않는다.
- **글자 크기 살짝 축소**: 첫 문단 앞에 아래 스타일을 넣는다.

```html
  <style>
  .page__content { font-size: 0.85em; }
  </style>
```
6. 본문에서 `#`(h1)은 절대 쓰지 않는다. 큰 구분(Lv.1, 미션 이름 등)은 `##`, 그 안의 개별 문제·단계는 `###`, 그 밑의 하위 항목(문제 상황/시도한 방법 등)은 `####`로 써서 목차가 계단식으로 들여써지게 한다.
### 6.1 문제풀이(practice) 글 템플릿

`type: practice`인 글은 위 STAR 템플릿 대신 아래 골격을 따른다.

```markdown
---
title: "<주제>"
subtitle: "<카드에 보일 한 줄 소개>"
excerpt: "<subtitle과 동일>"
date: YYYY-MM-DD
categories: Cloud
type: practice
topic: "<문제 제목>"
level_order: 10
tags: [태그1, 태그2, ...]
---

<style>
.page__content { font-size: 0.85em; }
</style>

## <큰 구분 — 예: Lv.1 기본 변형>

## <개별 문제 제목>

### 문제 상황
...

### 시도한 방법
\`\`\`
(명령/코드)
\`\`\`

### 막혔던 점
🔴 (실제 겪은 내용 — 아직 없으면 `> (...)`)

### 해결 과정
🟢 ...

### 배운 점
💡 ...
```
7. 글 맨 위(첫 문단 전)에 아래 스타일을 넣어 본문 글자 크기를 살짝 줄인다.
8. 파일 이름과 나머지 앞머리 규칙은 `CLAUDE.md`를 따르되, 아래 네 항목은 꼭 채운다.
   - `categories: Cloud`
   - `type: practice`
   - `topic: "<문제 제목>"` — cloud.md의 "🧩 문제풀이" 섹션이 이 값으로 묶는다
   - `level_order` — 같은 topic 안에서 Lv.1→Lv.2→Lv.3→보너스 순으로 카드가 뜨도록 10/20/30/90 중 하나
   - `subtitle` — 카드에 보일 한 줄 소개
9. `_posts/cloud`(또는 `CLAUDE.md`에 적힌 실제 경로)에 파일을 만든다.
10. 다 쓰면 나에게 먼저 보여줘. 내가 좋다고 하기 전에는 커밋하지 마.
11. 내가 확인하면 커밋하고 push 해줘.
