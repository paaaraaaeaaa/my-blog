# 문제풀이 devlog 만들기

사용자가 `/practice`와 함께 문제 링크를 준다: $ARGUMENTS

풀이 글은 `Cloud` 카테고리로 저장되지만, 화면에서는 **Database 페이지의 문제 카드 아래 "Lv1 → Lv2 → Bonus" 단계 목록**으로 보인다.
연결 고리는 글의 `topic` 값과 `_data/database_links.yml` 문제 항목의 `topics` 값이다.

## 순서

1. **링크 읽기**: 문제 내용을 전부 읽는다. 스크롤·펼치기·로그인·이미지 때문에 못 읽은 부분이 있으면
   "이 뒷부분이 안 열려요, 캡처해서 보내줄래요?"처럼 **정보 확인만** 한다. 다 읽었으면 묻지 말고 진행한다.
2. **애매할 때만 확인** (둘 다 명확하면 묻지 않는다)
   - 개인 미션인지 팀 미션인지, 팀이면 우리 팀이 배정된 미션이 뭔지
   - 문제가 여러 개일 때 전부 다루는지 일부만 다루는지
3. **문제 카드 연결** — `_data/database_links.yml`을 연다.
   - 이 링크(`url`)가 이미 있으면 그 항목의 `topics`에 이번 글의 `topic`이 있는지 확인하고, 없으면 추가한다.
   - 없으면 `category: "문제"` 항목을 새로 추가한다: `title`(문제 제목), `module`, `topics: ["<topic>"]`, `url`(받은 링크), `description`.
   - 이 수정도 글과 같이 보여주고 같이 커밋한다.
4. **파일 만들기**: `_posts/Cloud/문제풀이/YYYY-MM-DD-<영문-주제>-lv1.md` (레벨을 합쳤으면 `-lv2-lv3`, 보너스는 `-bonus`)
5. **본문 작성**: 문제(또는 단계)마다 `문제 상황 → 시도한 방법 → 막혔던 점 → 해결 과정 → 배운 점` 순서.
   - 소요 시간("15분" 등)은 적지 않는다.
   - `막혔던 점`/`배운 점`은 실제 경험 자리다. 아직 모르면 `> (...)` 빈칸으로 두거나 초안으로 채우고,
     채웠다면 "이 문단들은 실제 경험으로 바꿔 써야 한다"고 표시한다.
   - 문단 맨 앞 이모지로 색 블록을 만든다: 🔴 막혔던 점 · 🟢 해결 과정/확인 방법 · 💡 배운 점/핵심 개념 · ⚠️ 주의할 점
6. `post-checker` 에이전트로 검사하고, 결과를 글·yml 수정과 함께 나에게 보여준다.
   내가 좋다고 하기 전에는 커밋하지 마.
7. 내가 확인하면 커밋하고 push 한다. 커밋 메시지: `practice: <topic> <레벨>`

## 앞머리 (전부 필수)

```yaml
---
title: "Lv1 · <이 레벨에서 한 일>"
subtitle: "<한 줄 소개>"
excerpt: "<subtitle과 같은 문구>"
date: YYYY-MM-DD
categories: Cloud
module: 1
type: practice
topic: "<문제 제목>"
level_order: 10
tags: [태그1, 태그2, 태그3]
comments: true
toc: true
toc_sticky: true
mermaid: true
---
```

| 항목 | 규칙 |
|---|---|
| `title` | **`Lv1 · 제목`**, `Lv2+Lv3 · 제목`, `Bonus · 제목` 형식. ` · ` 앞부분이 Database 카드의 레벨 라벨로 자동 분리된다. 레벨이 없는 미션은 그냥 제목 |
| `module` | 가장 최근 학습노트의 `module` 값 |
| `topic` | 같은 문제의 모든 레벨 글에 **똑같은 문자열**. `database_links.yml`의 `topics`와도 같아야 한다 |
| `level_order` | Lv1=10, Lv2=20, Lv3=30, 보너스=90. 레벨을 합쳤으면 낮은 쪽. 레벨이 없으면 게시 순서대로 10, 20, 30… |
| `date` | `YYYY-MM-DD` 하이픈 표기 |
| `layout` | 쓰지 않아도 된다(`_config.yml`이 `single`을 넣음). 쓰려면 `single`만. `post`는 목차·콜아웃이 깨진다 |

## 본문 골격

제목 단계는 `##` 큰 구분 → `###` 개별 문제 → `####` 하위 항목. **`#`(h1)은 쓰지 않는다.**
`<style>`, 글자 크기 조절 코드는 **넣지 않는다.** (모든 글이 같은 크기로 읽혀야 한다 — DESIGN.md 5장)

````markdown
## Lv.1 <큰 구분>

### <개별 문제 제목>

#### 문제 상황
...

#### 시도한 방법
```bash
(명령/코드)
```

#### 막혔던 점
🔴 (실제 겪은 내용 — 아직 없으면 `> (...)`)

#### 해결 과정
🟢 ...

#### 배운 점
💡 ...

## 더 학습하면 좋은 개념
- **개념** — 한 줄 설명 + 왜 배워야 하는지

## 참고 자료
- [공식 문서](https://...)
````
