# 디자인 수정하기

사용자가 바꾸고 싶은 것을 준다: $ARGUMENTS
기준 문서는 저장소 루트의 `DESIGN.md`다. 작업 전에 **반드시 전부 읽는다.**

## 순서

1. **요청 정리** — 무엇을, 어느 페이지에서, 왜 바꾸는지 한 문장으로 되짚는다.
   스크린샷이 있으면 먼저 본다. 애매하면 **한 가지만** 묻는다. (예: "모바일에서도 같이 바꿀까요?")
2. **재사용부터** — `DESIGN.md` 4장 컴포넌트 카탈로그에서 쓸 수 있는 클래스를 먼저 찾는다.
   새 클래스를 만들기 전에 "기존 ○○를 쓰면 안 되는 이유"를 스스로 한 줄로 적어본다.
3. **어디를 고칠지 정한다** — 아래 표에 없는 곳은 고치지 않는다.

   | 바꾸는 것 | 고칠 파일 |
   |---|---|
   | 색·글꼴·간격·모서리 값 | `assets/css/tokens.css` (다크 `:root`와 라이트 `:root[data-theme="light"]` **둘 다**) |
   | 컴포넌트 모양 | `assets/css/site.css`의 해당 번호 섹션 |
   | 페이지 구조 | `index.md`, `cloud.md`, `Database.md`, `Projects.md`, `404.md` |
   | 상단바 | `_includes/masthead.html` |
   | 글 머리 정보줄·시리즈 표시 | `_includes/page__meta.html` |
   | 동작(JS) | `_includes/footer/custom.html` |
   | 섹션·아이콘 같은 데이터 | `_data/*.yml` |

4. **구현 규칙**
   - `site.css`와 페이지 파일에 `#hex`, `rgb()`를 쓰지 않는다. 필요한 색은 `tokens.css`에 토큰으로 만들고 **두 테마 값을 모두** 넣는다.
   - 카테고리 색은 정보용(Cloud·Database·Projects 구분)으로만, `--glow`는 "지금 여기" 표시에만 쓴다.
   - 외부 위젯 이미지(뱃지, 통계)를 추가하면 `data-src-light`로 라이트용 주소도 준다.
   - 코드 블록은 두 테마 모두 어둡다(`--c-code-*`). 코드 블록 안 요소는 `--c-code-*` 토큰만 쓴다.
   - 새 애니메이션은 사용자 동작에 반응하는 것만. `prefers-reduced-motion`에서 꺼지는지 확인한다.
   - 640px(모바일)과 1024px(1열 전환) 두 지점에서 깨지지 않게 한다.
   - UI 문구는 짧은 구어체("곧 출발", "링크 복사하기").
5. **검사** — `design-guard` 에이전트로 바뀐 파일을 검사하고 ❌ 항목을 고친다.
   가능하면 `bundle exec jekyll serve`로 **다크·라이트 두 테마 모두** 눈으로 확인한다.
6. **문서 갱신** — 새 컴포넌트는 `DESIGN.md` 4장 표에 한 줄, 토큰을 추가했으면 2장 표에 두 테마 값을 적는다.
7. 바뀐 부분과 검사 결과를 보여준다. 내가 좋다고 하기 전에는 커밋하지 마.
8. 내가 확인하면 커밋하고 push 한다. 커밋 메시지: `design: <무엇을 바꿨는지>`
