# 학습 노트 만들기

규칙의 기준은 `CLAUDE.md`(글 구조·게시 규칙)와 `DESIGN.md`(front matter가 화면에 쓰이는 방식)다.

## 순서

1. 먼저 나에게 물어봐 — "뭘 배웠어요?"
   내가 답하기 전에는 글을 쓰지 마. 답이 짧으면 STAR(상황·과제·행동·결과) 중 빈 곳을 **한 번에 하나씩만** 되물어.
2. 아래 값을 **스스로 계산해서** 채운다. 나에게 묻지 않는다.
   - **module**: `_posts/Cloud/학습노트/`에서 가장 최근 글의 `module` 값. 내가 "새 모듈 시작"이라고 했으면 +1 하고 `/module` 스킬을 먼저 안내한다.
   - **N일차**: **모듈별로 리셋**된다. `_data/module_schedule.yml`의 해당 module `start` 날짜를 1일차로 두고, 글 날짜까지 주말과 `_data/holidays.yml`의 날짜를 뺀 평일 수.
     확인용: **같은 module** 안에서 가장 최근 학습노트의 N + 그 뒤 평일 수와 같아야 한다(다른 module의 글은 비교 대상이 아니다). 오늘이 그 module의 첫 글이면 N은 1이다. 다르면 나에게 알려준다.
3. 파일명을 만든다. **module이 1이면** `_posts/Cloud/학습노트/YYYY-MM-DD-dayN.md`, **module이 2 이상이면** `_posts/Cloud/학습노트/YYYY-MM-DD-m{module}-day{N}.md`로 만든다.
   (서로 다른 module의 글이 같은 N일차 제목("1일차" 등)을 가질 수 있어서, 파일명이 겹치면 Jekyll 퍼마링크가 충돌한다. module 번호를 파일명에 넣어 구분한다.)

   앞머리는 아래 형식 그대로.

   ```yaml
   ---
   title: "N일차"
   summary: "<오늘 배운 것 한 줄 — 본문 첫 줄 # 오늘 배운 것: 뒤와 똑같이>"
   excerpt: "오늘 한 일을 한두 문장으로. Cloud 달력 칸·최근 글·검색 미리보기에 그대로 보인다."
   layout: single
   categories: [Cloud]
   module: 1
   type: daily
   date: YYYY-MM-DD
   tags: [태그1, 태그2, 태그3]
   comments: true
   toc: true
   toc_sticky: true
   mermaid: true
   ---
   ```

   - `tags`는 3~5개. **앞의 2개가 달력 칸에 보이니** 가장 대표적인 것을 앞에 둔다.
   - `부트캠프`처럼 모든 글에 해당하는 태그는 쓰지 않는다. 기술 이름은 소문자로 통일한다(`git`, `github`, `css`).
   - 본문 첫 줄에 `# 오늘 배운 것: <한 문장>` 부제목을 둔다. (목차에서는 자동으로 빠진다)
   - 그 한 문장을 `summary`에도 똑같이 넣는다. **Cloud 달력 칸에 이 문장이 크게 보인다.** 30자 안팎, 핵심 키워드가 앞에 오게.
   - 본문은 `CLAUDE.md` 6장 STAR 템플릿을 따른다.
   - `<style>`, 글자 크기 조절 코드, 인라인 `style="..."`는 **넣지 않는다.** (DESIGN.md 5장)
4. 새 기술 태그를 처음 썼다면 `_data/skills.yml`에 아이콘을 추가할지 제안한다. (skillicons에 있는 기술일 때만)
4-1. 오늘 실습한 원본 프로젝트(`chap0N-.../src/...`)가 있으면, 관련 있는 파일만 골라 `assets/code/YYYY-MM-DD-제목/`에 같은 하위 폴더 구조(예: `a_controlflow/Application01.java`)로 복사하고, 본문 도입부(패키지 구성을 소개하는 문단 다음)에 `{% include code-popup.html dir="YYYY-MM-DD-제목" %}`를 **글당 한 줄만** 넣는다.
   (버튼을 누르면 그 날짜 폴더 전체가 폴더 → 파일 트리 팝업으로 뜨고, 파일을 고르면 내용을 보여준다. 코드 블록마다 따로 넣지 않는다.)
   (원본 프로젝트 폴더 자체는 `_config.yml`의 `exclude`에 `chap*`로 이미 막혀 있어 사이트에 그대로 발행되지 않는다. 그래서 필요한 파일만 이렇게 복사해서 보여준다.)
4-2. **실행 결과 파일**: 4-1에서 복사한 폴더 안의 `main`이 있는 `.java`마다, 같은 폴더에 `X.out.txt`(실행 결과)를 만든다. 코드 팝업이 `.java`를 열면 `코드 | 실행 결과` 탭으로 보여준다. `.out.txt`는 파일 목록에는 나오지 않고 `.java` 옆에 `+ 실행 결과`로 붙는다.
   - 폴더의 모든 `.java`를 한 번에 `javac -encoding UTF-8 -d <임시폴더>`로 컴파일하고(폴더 구조와 package 선언이 달라도 파일 목록을 직접 넘기면 된다), 클래스마다 **새 임시 폴더를 작업 디렉터리로** 해서 `java -Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8 -cp <임시폴더> 패키지.클래스 < /dev/null`로 실행한다(타임아웃 10초, stdout+stderr를 합쳐 기록).
   - 입력(Scanner·System.in)이 필요한 프로그램, 타임아웃, 출력이 빈 프로그램은 건너뛴다. 예외로 끝나는 프로그램은 스택트레이스까지 그대로 기록한다(스택트레이스 속 절대경로는 지운다).
   - UTF-8(BOM 없음), 줄바꿈 LF. 한글이 깨졌는지(�) 확인한다. 200줄이 넘으면 앞 200줄 + `... (이하 생략)`.
   - 본문에서 "실행해 보니 ~가 출력됐다"고 쓰는 문장은 이 결과 파일과 일치해야 한다.
4-3. **용어집·태그·관련 글은 자동이다.** 따로 파일을 고치지 않는다. 단, 용어집에 올라가려면 개념 카드를 `- **용어**` 바로 아래 `  - 한 줄 정의`로 시작해서 쓰고(첫 하위 항목이 용어집에 보이는 설명이 된다), 관련 글·태그 모아보기가 잘 묶이도록 태그 철자를 이전 글과 똑같이 쓴다(`java`, `exception`).
5. `post-checker` 에이전트로 검사하고, 결과를 글과 함께 나에게 보여준다.
   내가 좋다고 하기 전에는 커밋하지 마.
6. 내가 확인하면 커밋하고 push 한다. 커밋 메시지: `post: N일차 — <excerpt 앞부분>`
