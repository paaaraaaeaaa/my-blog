# 문제풀이 devlog 만들기

사용자가 `/practice`와 함께 문제 링크를 준다: $ARGUMENTS

아래 순서대로 해줘.

1. 링크를 열어서 문제 내용을 전부 읽는다. 한 번에 다 안 열리면(스크롤·펼치기 필요, 로그인 필요, 이미지라 못 읽음 등) 읽을 수 있는 만큼 읽고 부족한 부분을 알려줘 — 이건 "뭘 배웠어요?" 같은 질문이 아니라 "이 뒷부분이 안 열려요, 캡처해서 보내줄래요?" 같은 정보 확인 질문이다. 이 확인이 필요 없으면 묻지 말고 바로 진행한다.
2. 아래 두 가지가 애매하면만 짧게 확인한다.
   - 개인 미션인지 팀 미션인지, 팀이면 우리 팀이 배정된 미션이 뭔지
   - 문제가 여러 개일 때 전부 다루는지 일부만 다루는지
3. 문제(또는 미션의 단계)마다 `문제 상황 → 시도한 방법 → 막혔던 점 → 해결 과정 → 배운 점` 순서로 정리한다. 시간(몇 분 걸렸는지)은 적지 않는다.
4. `막혔던 점`/`배운 점`은 실제 경험을 적는 자리다. 아직 안 겪었으면 빈 칸(`> (...)`)으로 남겨도 되고, 자연스러운 초안으로 채워도 된다 — 채웠다면 "이 문단들은 실제 경험으로 바꿔 써야 한다"고 나에게 표시해줘.
5. 아래 이모지를 해당 문단 맨 앞에 붙여서 색 블록으로 구분한다(custom.html에 이미 스타일 있음, 새로 안 만들어도 됨).
   - 🔴 막혔던 점
   - 🟢 해결 과정 / 확인 방법
   - 💡 배운 점 / 핵심 개념
   - ⚠️ 주의할 점 / 막힐 수 있는 지점
6. 본문에서 `#`(h1)은 절대 쓰지 않는다. 큰 구분(Lv.1, 미션 이름 등)은 `##`, 그 안의 개별 문제·단계는 `###`, 그 밑의 하위 항목(문제 상황/시도한 방법 등)은 `####`로 써서 목차가 계단식으로 들여써지게 한다.
7. 글 맨 위(첫 문단 전)에 아래 스타일을 넣어 본문 글자 크기를 살짝 줄인다.
8. 파일 이름과 나머지 앞머리 규칙은 `CLAUDE.md`를 따르되, 아래 네 항목은 꼭 채운다.
   - `categories: Cloud`
   - `type: practice`
   - `topic: "<문제 제목>"` — cloud.md의 "🧩 문제풀이" 섹션이 이 값으로 묶는다
   - `subtitle` — 카드에 보일 한 줄 소개
9. `_posts/cloud`(또는 `CLAUDE.md`에 적힌 실제 경로)에 파일을 만든다.
10. 다 쓰면 나에게 먼저 보여줘. 내가 좋다고 하기 전에는 커밋하지 마.
11. 내가 확인하면 커밋하고 push 해줘.
